### 1.2 ปัญหาที่ต้องแก้ (Pain points)
1. **Report QC ไม่ออก/ล่าช้า** — กำหนด 7 วัน แต่ช่วง มิ.ย.–ก.ค. ไม่มี Report QC ออกเลย `[B 01:46:55]` `[B 01:47:37]`
2. **ข้อมูล Defect ไม่เป็นมาตรฐาน** — อาการเดียวกันตั้งชื่อต่างกัน, กรอกจำนวนผิด, ใช้รูปเดียวกันซ้ำหลายเครื่อง → หัวหน้า QA ต้องเปิดรูปตรวจทีละตัวก่อนส่งเคลม `[B 01:33:38]` `[B 01:38:12]`
3. **เปิดแผนซ้ำ / ใช้ Checklist ผิดรุ่น** `[B 00:14:41]` `[B 00:24:59]`
4. **ที่เก็บรูป/วิดีโอเต็ม** — ย้ายด้วยมือ ลิงก์รูปกระจายตามบุคคล `[B 00:36:29]` `[B 00:38:51]`
5. **งานซ้ำซ้อน** — เก็บข้อมูล NCP แยกอีกชุด ทำ Dashboard แยก ประเมิน Vendor ด้วยมือ `[A 45:31]` `[A 48:43]`
6. **ไม่มีการติดตามสถานะ** — ไม่รู้ว่าแผนไหนค้าง, จัดซื้อหยิบ NCP ไปหรือยัง; ปัญหาหน้างานรู้ตอนท้ายวัน (~16:30) ซึ่งกระทบการขาย `[B 01:39:46]` `[B 00:52:27]`
7. **ระบุตัวผู้ใช้ด้วย Gmail ส่วนตัว** — ตรวจสอบย้อนหลังไม่ได้ `[A 04:26]` `[A 04:54]`
8. **NCP กระจายต่อ SKU** — 1 Invoice มีหลาย NCP ออกห่างกันหลายสัปดาห์ หักเงิน/ต่อรองยาก `[A 22:15]` `[A 25:39]` `[A 47:08]`
9. **จำนวน QA ไม่ขึ้นทันทีตอนเปิดแผน** ต้องบันทึกก่อนแล้วกลับมาดู `[B 01:17:55]`

## 2. เป้าหมายโครงการ (Objectives)

| # | เป้าหมาย | ตัวชี้วัดความสำเร็จ (ตั้งต้น — ยืนยัน ❓ E14) |

| O1 | การตรวจรับทั้งหมดทำในระบบเดียว บนมือถือ | 100% ของแผนที่เปิดใหม่หลัง Go-live อยู่ใน QCheck (ยกเว้นส่วนที่ตกลงตรวจกระดาษ) |

| O6 | ติดตามงานได้แบบ near real-time | Status board + แจ้งเตือน QA Reject/ปัญหาในตัวอย่าง ทันทีที่เกิด |
| O7 | ส่งต่อข้อมูลเคลมและวัดผล Vendor | จัดซื้อเห็นสถานะ NCP ในระบบ (Phase 2), Dashboard คุณภาพ Vendor ใช้แทนงานมือ (Phase 3) |

### 4.2 ขอบเขตด้านแพลตฟอร์ม
- **Web App (PWA)** เดียว ใช้ได้ทั้งมือถือ (หลัก) และ Laptop โดยไม่ต้องติดตั้งจาก Store `[B 00:05:02]` `[B 02:07:48]`
- "ใช้บน laptop ได้แบบไม่มีปัญหา" นิยามเป็นรายฟังก์ชันใน **02 §5.2 (Device × Flow)** — เช่น รูปหลักฐานบน laptop ใช้กล้อง USB หรือ "ถ่ายต่อบนมือถือ"
- รองรับ Android (Chrome), iOS (Safari ติดตั้งเป็น Home Screen app — ผู้ตรวจ iOS 17+), Laptop (Chrome/Edge), จอ TV
- สแกน QR/Barcode ด้วยกล้อง และเครื่องยิง/PDA แบบ keyboard-wedge `[B 00:17:01]` `[B 00:18:29]`
- **ทนเน็ตไม่เสถียร** — ตรวจได้โดยไม่มีเน็ต แล้วซิงค์ภายหลัง `[B 02:08:53]` `[B 02:12:39]`

### 6.1 ช่วงเปลี่ยนผ่าน (ระหว่าง Pilot R1.0 → Go-live Phase 1 → Phase 2)
1. **Pilot R1.0**: แผนใน Pilot บันทึก QC ใน QCheck เป็นหลัก (`qa_mode = EXTERNAL`) — QA ยังทำในระบบเดิมโดยอ้างอิง **เลขแผน QCheck** (ไม่เปิดแผนซ้ำ); ระบบ export รายการแผนที่ QC เสร็จให้ QA ได้ · ไม่บันทึกซ้ำสองระบบทุกเครื่อง (กระดาษ/AppSheet เป็นสำรองเมื่อระบบล่มเท่านั้น)
2. **Go-live Phase 1 (R1.1)**: แผนใหม่ทั้งหมดเปิดใน QCheck และ QA ทำในระบบ (`qa_mode = IN_APP`); แผน Pilot ที่ยังไม่จบ หัวหน้าแปลงเป็น IN_APP ได้ · AppSheet เป็น read-only (DEC-07)
3. **ก่อน Phase 2**: NCP ยังออกด้วย Excel แบบเดิม แต่ใช้ข้อมูล/รูปจาก Report ใน QCheck · เมื่อ Phase 2 เปิด แผนที่ COMPLETED แต่ยังไม่มี NCP สามารถรวมเข้า NCP ได้
