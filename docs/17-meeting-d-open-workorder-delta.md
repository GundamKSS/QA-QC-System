## 1. กฎใหม่จาก Meeting D

### 1.1 Need ของใบงาน = "เป้า 10% ของล็อต − ที่ตรวจจริงสะสม" ⚠️
- ใบงานแรก: ระบบเด้ง **Need = 10% ของล็อตเต็ม** (ล็อต 500 → 50) ไม่ว่าครั้งนั้นจะเรียกของเข้าเท่าไร `[D 00:53]` `[D 15:22]` `[D 15:40]`
- ใบงานถัดไป: **Need = เป้าของล็อต − True สะสม** เช่น ตรวจแล้ว 10 → Need 40; ตรวจแล้ว 30 → Need 20; ครบ 50 → ไม่มีเป้าเหลือ `[D 06:03]` `[D 06:43]` `[D 15:40]` `[D 18:06]`
- "ไม่ต้องสนใจว่าเรียกเท่าไร สนใจแค่ว่าพอเปิดใบงานให้เอา **ล็อตลบทรู**" `[D 15:22]` (ต่างจาก Meeting C: Need = 10% ของจำนวนที่เรียก ไม่เกินส่วนที่ขาด)

### 1.2 ข้อจำกัดของ "จำนวนเรียกเข้า" ✅🔶
- จำนวนเรียกเข้า **ต้อง ≥ Need** (ห้ามต่ำกว่า, ระบบเตือนสีแดงและห้ามบันทึกถ้าต่ำกว่า) และ **ห้ามเกินส่วนของล็อตที่ยังไม่เคยเรียก** `[D 04:54]` `[D 05:12]` `[D 07:59]` `[D 12:04]` `[D 12:21]` `[D 14:30]`
- เรียกมากกว่า Need ได้ (เช่น เรียก 200 แต่ Need ยังเป็น 50) `[D 05:12]` `[D 12:39]` — เหตุที่โรงงานเรียกทยอย: พื้นที่หน้างานไม่พอ `[D 10:26]` `[D 25:24]`
- ตัวอย่างล็อต 100 ตัว: โรงงานเรียก 20 (พื้นที่พอแค่นี้) → Need 10 (10% ของล็อต) → ใส่ 9 ไม่ได้ `[D 09:32]` `[D 11:20]` `[D 11:26]`
- ตัวอย่างล็อต 500 ที่คลังรับได้ 200: เรียก 200 → Need 50 → มอบหมาย 2–5 คน → เหลือ 300 ที่ยังไม่เรียก `[D 25:12]` `[D 25:28]`

### 1.3 "True" = ตรวจจริง นับอย่างไร ✅
- นับเมื่อผู้ตรวจ **กดส่ง (Finish) หน่วยนั้นใน Checklist** (1 เครื่อง = 1) `[D 01:26]` `[D 01:35]`
- **นับ Serial ไม่ซ้ำภายในแผน**: เลขแผนเดียวกัน Serial เดียวกัน แม้อยู่คนละใบงาน ให้นับเป็น 1 (กันการก๊อปผลตรวจโดยไม่เปลี่ยน Serial เพื่อให้ครบเป้า) `[D 01:35]` `[D 02:09]` — หลักการ: "ปิดทุกช่องที่เขาจะโกงได้" `[D 12:58]`
- จะ "ตรวจจริง" เกินเป้าได้ ไม่จำกัด `[D 07:53]` `[D 07:59]`

### 1.4 เปิดใบงานได้กี่ใบ/วัน และเมื่อไรเปิดใบถัดไปได้ 🔶
- **วันหนึ่งเปิดได้ใบเดียวต่อแผน** (วันเดียวกันห้ามเปิดซ้ำ) แล้วใช้ใบนั้นทำงานได้ต่อเนื่อง `[D 02:44]` `[D 19:27]` — เหตุผล: ผูกวันเรียกเข้ากับวันที่ตรวจได้ง่าย `[D 19:37]`
- ผู้พัฒนาเสนอเพิ่ม: **ห้ามเปิดใบที่ 2 ถ้าใบก่อนหน้ายังไม่เคยมีการตรวจเลย (True = 0)** อย่างน้อยต้องตรวจ 1 เครื่องก่อน `[D 19:13]` `[D 21:01]` — QA Head รับ ("ก็ได้") แต่มีกรณีโรงงานเรียกเพิ่มข้ามวัน (ข้อ 1.5)
- ใบงานที่เปิดวันนี้แต่ตรวจวันอื่นได้ เพราะมี FK ผูกใบงาน↔ผลตรวจอยู่แล้ว `[D 20:17]` `[D 20:40]`

### 1.5 ✅ (ผู้ใช้ยืนยัน 21 ต.ค.) กฎ "ไม่สำเร็จ"
เปิดใบที่ 1 แล้วไม่ตรวจเลย → เปิดใบที่ 2 แล้วตรวจเสร็จทั้งหมดหรือบางส่วน และทำต่อ ๆ ไปจนครบทั้ง **10% (True)** และ **100% ของล็อต (เรียกเข้าครบ)** → ใบก่อนหน้าที่ไม่เคยมีการตรวจเลยขึ้น **"ไม่สำเร็จ"** และ **ไม่นำค่าไปคำนวณใด ๆ** แค่เก็บเป็นประวัติว่ามีรายการนี้อยู่

### 1.5b ใบงานที่ไม่ได้ทำเลย (บันทึกจากเสียง): "ไม่สำเร็จ" / ยกเลิก 🔶
- กรณีโรงงานเรียกเข้า 50 วันแรกแล้วยังไม่ได้ตรวจ วันถัดไปเรียกอีก 50 (ล็อต 100): ทั้งสองใบมี Need เท่ากัน (10) — พอใบหนึ่งตรวจครบเป้า **อีกใบที่ไม่มีการตรวจเลยขึ้นสถานะ "ไม่สำเร็จ"** ทันที ส่วนใบที่ครบเป็นสถานะสุดท้าย "สำเร็จ" `[D 21:11]` `[D 22:07]` `[D 23:56]` `[D 24:14]` `[D 26:24]`
- ทางเลือกที่พูดถึง: ให้ผู้ใช้ **กดยกเลิก** ใบที่ไม่ใช้เอง `[D 22:50]`
- มีสถานะแยก "ไม่สำเร็จ" กับ "กำลังทำ" เพื่อใช้ทำ KPI/สถานะภายหลัง `[D 24:38]` `[D 24:45]`
- เงื่อนไขที่ตั้ง: เมื่อ **จำนวนเรียกเข้ารวมครบทั้งล็อต** และใบงานใดยังตรวจ = 0 → ใบนั้น "ไม่สำเร็จ" `[D 23:56]` `[D 24:14]`
