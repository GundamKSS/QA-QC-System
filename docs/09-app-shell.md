# 09 — App shell มือถือ (Bottom tab bar)

> สถานะ 19 ต.ค. 2026: **ลงโครงแอปและ Home ข้อมูลตัวอย่างแล้ว** — มี top bar/sidebar/4 mobile tabs, ค้นหา, แจ้งเตือนว่าง และหน้าเพิ่มเติมสำหรับบัญชี/logout · โมดูลธุรกิจอื่นยังไม่เปิดใช้
> จุดประสงค์: หลัง login บนมือถือต้องรู้สึกเป็นแอป ไม่ใช่เว็บที่มีแค่ลิงก์ — มีแถบนำทางติดด้านล่างจอตลอดหน้าที่เป็นศูนย์กลางงาน
> อ้างอิง: S02 ใน [02](02-spec-functional.md) · breakpoint ใน [04 §5](04-spec-technical.md) · งาน 1.2 ใน [05](05-work-plan.md) · โครงแท็บใน [wireframes/qcheck-wireframe.html](wireframes/qcheck-wireframe.html)
> หน้า Login ยังใช้ [07](07-login-art-direction.md) — กลุ่ม `(auth)` **ไม่มี** tab bar

---

## 1. ตัดสินใจ

หลังเข้าสู่ระบบบนมือถือ (ความกว้าง < 768 px) ใช้ **โครงแอป**:

1. **Top app bar** — ชื่อหน้าปัจจุบัน + สถานะซิงค์ถ้ามี
2. **เนื้อหาเต็มความกว้าง** — เลื่อนในพื้นที่ระหว่างแถบบนกับแถบล่าง
3. **Bottom tab bar** — 5 แท็บหลัก ติดขอบล่าง ไอคอน + คำไทย สั้น ๆ (โทนเดียวกับแอปมือถือทั่วไป เช่น Instagram: แถบคงที่ tap แล้วสลับหน้า ไม่ใช่เมนูแฮมเบอร์เกอร์อย่างเดียว)

บนจอ ≥ 768 px ใช้ **sidebar ซ้าย** แทนแท็บล่าง (รายการเดียวกัน) — ไม่โชว์สองอันพร้อมกัน

โทนสีใช้ design tokens ชุดเดียวกับ Login (carbon / titanium / ember) จนกว่าจะมีงาน "ใส่ธีม" ใน WBS — ไม่สร้างชุดสีใหม่ในรอบนี้

## 2. แท็บ (ค่าตั้งต้น)

จำนวน **5 แท็บ** เสมอ (ปรับตามคำขอ 21 ต.ค. 2026: Home แยกเป็นแท็บแรก) (ห้าม 6+ เพราะนิ้วโป้งเอื้อมไม่ถึงและตัดคำไทย) · ลำดับซ้าย → ขวา · ป้ายไม่ใส่ภาษาอังกฤษในแถบ

ชุดตามบทบาท **หลัก** ของผู้ใช้ใน session (ถ้ามีหลายบทบาท ใช้บทบาทที่เลือก "ตรวจในฐานะ" ล่าสุด ถ้ายังไม่เลือกใช้บทบาทแรกตามลำดับ QC Insp. → QA Insp. → QC Head → QA Head → อื่น)

### 2.1 แท็บปัจจุบัน (21 ต.ค. 2026)

ทุกบทบาทมี **หน้าหลัก** เป็นไอคอนรูปบ้านทางซ้ายสุด ตามด้วยทางลัด 2 ช่องตามสิทธิ์ และจบด้วย **แจ้งเตือน · เพิ่มเติม**:

| บทบาทหลัก | 5 แท็บจากซ้ายไปขวา |
|---|---|
| QC Inspector | หน้าหลัก · งานของฉัน · สแกน · แจ้งเตือน · เพิ่มเติม |
| QA Inspector | หน้าหลัก · คิว QA · สแกน · แจ้งเตือน · เพิ่มเติม |
| QC Head | หน้าหลัก · แผน · งาน · แจ้งเตือน · เพิ่มเติม |
| QA Head | หน้าหลัก · แผน · คิว QA · แจ้งเตือน · เพิ่มเติม |
| Admin | หน้าหลัก · ตั้งค่า · แผน · แจ้งเตือน · เพิ่มเติม |
| Master Admin | หน้าหลัก · ข้อมูลหลัก · เช็กลิสต์ · แจ้งเตือน · เพิ่มเติม |
| Purchasing | หน้าหลัก · รายงาน · เช็กลิสต์ · แจ้งเตือน · เพิ่มเติม |
| PM / Management | หน้าหลัก · รายงาน · ข้อมูลหลัก · แจ้งเตือน · เพิ่มเติม |

หลายบทบาทใช้ลำดับบทบาทหลักเดิมและสิทธิ์รวมกัน โมดูลที่ยังไม่มีหน้า (คิว QA, สแกน, ตั้งค่า, รายงาน, เช็กลิสต์) คงแสดงแบบ disabled ผ่าน `ShellLink` และไม่พาไป 404; ไม่เพิ่มสิทธิ์หรือสร้างโมดูลใหม่เพื่อเติมแถบ

Home ใช้ `/home` โดยตรง ไม่ผูก active กับแท็บงาน/แผน และคิว QA ใช้ `/qa-queue` แยกจาก Home

## 3. พฤติกรรมแถบล่าง

1. **คงที่** ไม่เลื่อนตามเนื้อหา · พื้นหลังทึบ (ไม่โปร่งใสทับการ์ดงาน) · เส้น hairline บนสุด
2. ความสูงเนื้อหาแท็บ **56 px** + `env(safe-area-inset-bottom)` (กันปุ่ม Home / gesture bar ของ iPhone)
3. แต่ละแท็บ: ไอคอนบน (≈ 22–24 px) คำไทยล่าง (≈ 11 px) · เป้ากดเต็มคอลัมน์สูงอย่างน้อย 44 px ไม่นับ safe-area
4. **แท็บที่เลือก:** สีตัวอักษร/ไอคอนเข้มขึ้น (token `ti-50` หรือ `ember-500`) · **แท็บอื่น:** `ti-500` · ไม่ใช้สีอย่างเดียว (ไอคอนเปลี่ยนน้ำหนัก/เส้น vs เติม)
5. กดแท็บที่เปิดอยู่แล้ว → เลื่อนเนื้อหาขึ้นบนสุดของหน้านั้น (ไม่รีโหลดทั้งแอป)
6. Badge แจ้งเตือนเป็นตัวเลขบนไอคอน แท็บ 4 · สูงสุด "9+" · อ่านแล้วหาย · สี `ember-500` พื้นกลม
7. เนื้อหาทุกหน้าที่มีแท็บต้องมี `padding-bottom` พอให้การ์ดสุดท้ายไม่ถูกแถบบัง
8. แนวนอนมือถือ: แท็บยังอยู่ล่าง ความสูงอย่างน้อย 48 px + safe-area — ห้ามย้ายไปข้างจอใน R1.0
9. คีย์บอร์ดเปิด (`visualViewport` หด): **ซ่อนแท็บ** ชั่วคราว เพื่อไม่ให้ทับช่องกรอก แล้วโชว์กลับเมื่อปิดคีย์บอร์ด
10. ไม่มี WebGL ในกลุ่ม `(app)` — แถบเป็น DOM ล้วน

### 3.1 หน้าที่ **โชว์** แท็บ

S02 หน้าแรก, S03 แจ้งเตือน, S04 งานของฉัน, S05 สแกน (โหมดเลือก/รอสแกน), S09 สถานะซิงค์, S10 รายการแผน (มือถือ), S28 คิว QA, S30 ค้นหา, S31 เพิ่มเติม, รายการอื่นที่เป็นศูนย์กลางงาน

### 3.2 หน้าที่ **ซ่อน** แท็บ (เต็มจอ งานต่อเนื่อง)

| หน้า | เหตุผล |
|---|---|
| S01 Login | ยังไม่เข้าแอป |
| ตั้งรหัสผ่าน (ระบบกลาง) | นอก QCheck |
| S06 ตัวตรวจ Checklist | ปุ่ม ปกติ/ไม่ผ่าน อยู่ครึ่งล่าง — แท็บจะชนเป้ากด (02 §5.1) |

## 4. หน้าแรก / เมนู (S02) บนมือถือ

ไม่ใช้หน้าเว็บทักทายอย่างเดียวแบบ placeholder ปัจจุบัน

โครงเนื้อหา Home (แท็บ 1) จากบนลงล่าง:

1. ทักทายสั้นหนึ่งบรรทัด + รหัสพนักงาน (mono)
2. สรุปงาน: จำนวนรอรับ / กำลังทำ / Rework ค้าง (กดไปจุดนั้นในหน้า)
3. รายการการ์ดใบงานตาม FR-JOB-04
4. ทางลัดที่ไม่มีแท็บ (เช่น สถานะซิงค์) เป็นปุ่มในหน้า ไม่ซ้ำกับ 5 แท็บล่าง

แท็บ **เพิ่มเติม (S31)** รับของที่เคยอยู่บนหน้า placeholder: ออกจากระบบ, บทบาท, โหมดเครื่องส่วนกลาง, เวอร์ชัน (`QCheck v…`)

ออกจากระบบเป็น POST ไป `/api/auth/logout` (ย้ายจาก `/auth/logout` เมื่อ 26 ต.ค. 2026 — docs/19 ขั้น 6) — ห้าม GET

## 5. Laptop / แท็บเล็ต

| ความกว้าง | โครง |
|---|---|
| < 768 px | Bottom tab bar ตาม §2–3 |
| 768–1023 px | Sidebar ไอคอน+ป้าย แคบได้ หรือ list+detail — **ไม่** ใช้แท็บล่าง |
| ≥ 1024 px | Sidebar กว้างคงที่ + header · รายการนำทางชุดเดียวกับแท็บ (+ รายการหลังบ้านที่มือถืออยู่ในเพิ่มเติม) |

สลับขนาดจอระหว่าง session: โครงเปลี่ยนตาม breakpoint ไม่จำสถานะพับของ sidebar ข้ามอุปกรณ์

## 6. Accessibility และ PWA

- แท็บเป็น `nav` + `aria-label="เมนูหลัก"` · รายการเป็นลิงก์/`role="tab"` ที่ระบุ `aria-current="page"` เมื่อเลือก
- เป้าหมายรู้สึกเป็นแอปเมื่อติดตั้ง Home Screen (`display-mode: standalone`) — ในเบราว์เซอร์แถบ URL ของระบบยังอยู่ได้ ตามข้อจำกัด iOS ใน 04 §4.4
- ห้ามซ่อนแถบด้วย `position: fixed` แล้วเนื้อหาไม่มีช่องว่าง — ต้องจองที่ใน layout
- Reduced motion: สลับแท็บทันที ไม่สไลด์ทั้งหน้า

## 7. สถานะโค้ดปัจจุบัน

| รายการ | สถานะ |
|---|---|
| `(app)/layout.tsx` | ตรวจ session ใน Suspense; top bar รับ roles, sidebar รับ user; fallback เป็นสีพื้นพร้อมข้อความโหลดสำหรับ screen reader และ shell ทั้งหน้าเฟดเข้า 560 ms |
| Home | ข้อมูลตัวอย่าง 5 แผน/3 ข้อบกพร่อง มีป้าย Demo; KPI คำนวณจากชุดข้อมูลเดียวกับตาราง; ค้นหาแผน/Invoice/รุ่นแล้วกด Enter |
| เมนูตามบทบาท | `components/shell/nav.ts` ใช้กติกาเดียวกับ `lib/auth/page-access.ts`; sidebar/mobile ซ่อนเมนูที่บทบาทเข้าไม่ได้ · ปุ่มเปิดแผน/ข้อมูลหลักตามสิทธิ์ |
| Mobile tabs | 5 รายการ, Home แยกชัดเจน, active state, safe-area, กดซ้ำเลื่อนบนสุด; ซ่อนเมื่อ viewport หดจากคีย์บอร์ด |
| Sidebar | แสดงตั้งแต่ 768 px, รายการเพิ่มเติมตามบทบาท, ข้อมูลบัญชีและ logout |
| `/alerts` | หน้าว่าง “ยังไม่มีแจ้งเตือน” ตาม R1.0; ยังไม่เชื่อมบริการแจ้งเตือน |
| `/more` | โปรไฟล์/บทบาทและ logout แบบ POST; มือถือออกจากระบบได้ |
| หน้าอนาคต | แผน/งาน/สแกน/รายงาน/Master/settings ยังไม่มี business flow; เมนูและปุ่มสีจางพร้อม aria-disabled ไม่พาไป 404 |
| กลุ่ม `(app)` | ไม่มี WebGL |

ความต่างจากเป้าหมาย §2–4: คิว QA ยัง disabled จนมี `/qa-queue`; หน้า Home ยังเป็น dashboard ชุดข้อมูลตัวอย่าง ไม่ใช่รายการใบงานจริงตามผู้ใช้ · ยังไม่มี “ตรวจในฐานะ”, badge แจ้งเตือนจริง, sync/outbox หรือการรับงาน/ตรวจ Checklist

ผลตรวจอ้างอิง [login-progress.md](login-progress.md); ตรวจเพิ่มเติมด้วยบัญชีทดสอบบนระบบกลางจริง TEST001–TEST009 ครบ 9 บทบาทแล้ว ทั้ง Login, desktop/mobile menus, โปรไฟล์, Logout และป้องกันเข้าหน้าปัจจุบันหลัง Logout · กรณี API ล่ม/permission ผิดยังใช้ fixture

## 8. กติกาสิทธิ์หน้าจอที่ใช้ร่วมกัน

`lib/auth/page-access.ts` เป็นแหล่งกติกาเดียวสำหรับ `nav.ts` และ server DAL `requirePageAccess` (ตาม docs/02 §1) ไม่มีสิทธิ์พิเศษทางธุรกิจจาก ADMIN อัตโนมัติ; หลายบทบาทใช้สิทธิ์รวมกัน

| หน้า/การเข้าถึง | บทบาทที่อนุญาต |
|---|---|
| Home, แจ้งเตือน, บัญชี | ทุกบทบาทที่รู้จัก; มี page guard จริงแล้ว |
| แผนตรวจ | QC Head, QA Head |
| งาน QC | QC Head, QC Inspector |
| คิว QA | QA Head, QA Inspector |
| สแกน | QC Head/Inspector, QA Head/Inspector |
| Master อ่าน | Master Admin, QC Head, QA Head, PM, Management |
| Master แก้ไข | Master Admin เท่านั้น |
| รายงาน | Admin, QC/QA Head/Inspector, Purchasing, PM, Management |
| อุปกรณ์/ตั้งค่า | Admin เท่านั้น |
| Dashboard ผู้บริหาร | QA Head, Purchasing, PM, Management |
| Audit | Admin, QC Head, QA Head, Management |
| Checklist template อ่าน | ทุกบทบาท |

โมดูลนอก Home/แจ้งเตือน/บัญชียังไม่เปิดใช้: ตารางนี้กำหนด page admission สำหรับต่อยอด ไม่ได้หมายความว่ามี business flow หรือกรองข้อมูลรายแถวแล้ว ผู้ตรวจต้องเห็นเฉพาะรายงานของตัวเอง, Purchasing ดูเฉพาะรายงานที่ออกแล้ว, หัวหน้า QC ดู Audit ของแผนก และสิทธิ์แก้ไข/อนุมัติต้องตรวจซ้ำใน data query/API route (`guardApi`) ของแต่ละโมดูลตาม docs/02 เมื่อเริ่มสร้าง ห้ามใช้แค่เมนูหรือ layout เป็นตัวป้องกัน

Mobile: ทุกบทบาทมี Home แยกเป็นแท็บแรก รวม 5 แท็บตาม §2.1 เมนูอนาคตยัง disabled เหมือนเดิม
