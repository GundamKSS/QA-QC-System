แผนผังฐานข้อมูล QCheck

28 ตารางในฐานข้อมูล QCheck แบ่งเป็น 6 กลุ่ม เส้นแต่ละเส้นบอกว่าตารางไหนอ้างถึงตารางไหน กดที่ชื่อตารางในแผนภาพเพื่อดูว่าเก็บอะไรและมีไว้ทำไม · ภาพรวมทั้งโปรแกรมดูที่ แผนผังระบบ QCheck

ความเชื่อมโยงของตาราง

Foreign key (อ้างด้วย id จริง) ใช้ค่า / คัดลอกค่า (ไม่มี FK)

เส้นประจะแสดงเฉพาะตารางที่เลือก · เส้นจาก created_by / updated_by ไป users มีเกือบทุกตาราง จึงไม่ได้วาดไว้ · บนมือถือเลื่อนแผนภาพไปทางขวาได้

ข้อมูลเดินทางอย่างไรตอนเปิดแผนและเรียกของเข้า

  1. เลือก Vendor และพิมพ์เลข Invoice / PO → ระบบหาใน receipt_docs ด้วยเลขที่ normalize แล้ว ถ้ายังไม่มีก็สร้างหัวเอกสารใหม่ (วันที่ Invoice, จำนวน SKU, กำหนดตรวจ 90 วันจาก settings)
    vendors → receipt_docs ← settings
  2. เลือกรุ่นจาก models ซึ่งบอกว่าเป็นปั๊มนำเข้าหรือผลิตเอง ยี่ห้ออะไร และใช้แม่แบบใบตรวจไหน ระบบไม่ยอมให้เปิดแผนซ้ำสำหรับเอกสาร + รุ่นเดิม
    models → brands · pump_types · checklist_templates
  3. ออกเลขแผน QP-YYMM-NNNN จาก doc_counters แบบล็อกแถว จึงไม่ได้เลขซ้ำแม้มีคนกดพร้อมกัน
    doc_counters → plans.plan_no
  4. บันทึก plans พร้อมคัดลอก % QC ณ วันนั้นจาก qc_sampling_rates และผูกเวอร์ชันใบตรวจที่ Publish แล้ว ภายหลังแก้ % หรือแม่แบบ แผนนี้ก็ไม่เปลี่ยนตาม
    qc_sampling_rates · template_versions → plans
  5. เขียนแถวแรกใน plan_status_history (สถานะ OPEN) ทุกครั้งที่สถานะเปลี่ยนจะเพิ่มแถวใหม่ ไม่แก้แถวเก่า
    plans → plan_status_history
  6. เมื่อของมาถึง สร้าง work_orders หนึ่งใบต่อการเรียกเข้าหนึ่งครั้ง และกำหนดผู้รับผิดชอบ 2–5 คนใน work_order_assignees แผนจึงเปลี่ยนเป็น ASSIGNED
    plans → work_orders → work_order_assignees → users

ยังไม่มีในฐานข้อมูล

  • ผลตรวจรายเครื่อง, คำตอบรายหัวข้อ, รูป/วิดีโอ และ Defect ที่พบจริง: ตาราง fix_methods และ master_snapshots เตรียมไว้ให้ส่วนนี้ ตอนนี้จึงยังไม่มีตารางไหนอ้างถึง
  • NCP และใบลดหนี้ Supplier: doc_counters รองรับเลขรัน NCP / RW ไว้แล้ว
  • ค่าจริงของตาราง AQL ยังรอไฟล์จาก QA
