## 3. Storyboard (ลำดับเหตุการณ์)
| # | ผู้ใช้ทำ | ระบบแสดง |
|---|---|---|
| 1 | เปิด `/plans/new` | ค่าตั้งต้น = **Invoice**, ช่องว่าง, แถบสรุป QC "–" |
| 2 | เลือก Vendor + พิมพ์เลข Invoice (ออกจากช่อง) | เรียก server ตรวจหัวเอกสาร (normalize แบบเดียวกับ BR-01): **ใหม่** → ช่องวันที่ Invoice / จำนวน SKU ให้กรอก · **พบแล้ว** → กล่อง ⓘ แสดงวันที่, จำนวน SKU, แผนที่เปิดแล้ว (x/y) และช่องหัวเอกสารเป็นอ่านอย่างเดียว |
| 3 | กรอกวันที่ Invoice | แถบสรุปแสดง **กำหนด 90 วัน + นับถอยหลัง** (แดงถ้าเลยกำหนด) |
| 4 | เลือก Model | dropdown แสดงเฉพาะ Model ตามแหล่งที่มา (Invoice → นำเข้า, PO → ผลิตเอง) และใช้งานอยู่ · เติม Description ให้ (แก้ได้) · แสดง Brand / ประเภทปั๊ม / Checklist แบบอ่านอย่างเดียว (FR-PLAN-03) · ถ้า Model นี้มีแผนแล้วในเอกสารเดียวกัน → เตือนทันที "แผนนี้เปิดแล้ว: QP-… [ไปที่แผนเดิม]" |
| 5 | พิมพ์จำนวน 350 | **QC ต้องตรวจ 35** ขึ้นทันที (ใช้ % ปัจจุบันจาก server; 80→8, 81→9, 5→1) |
| 6 | กด "บันทึกแผน" | ปุ่มเปลี่ยนเป็น "กำลังบันทึก…" (กันกดซ้ำ) |
| 7a | สำเร็จ | ไปหน้าผลลัพธ์ (ดูข้อ 5 · K4) แสดง "เปิดแผน **QP-2610-0001** แล้ว" |
| 7b | ซ้ำ (มีคนเปิดก่อน) | กล่องเตือนบนฟอร์ม "แผนนี้เปิดแล้ว: QP-… [ไปที่แผนเดิม]" — ข้อมูลที่กรอกยังอยู่ |
| 7c | ช่องผิด | ข้อความไทยใต้ช่อง (จาก `fieldErrorMessage`) + โฟกัสช่องแรกที่ผิด + สรุปด้านบน "กรุณาแก้ช่องที่มีปัญหา" |
| 7d | DB ล่ม | ข้อความจาก `dbProblemMessages` บนฟอร์ม ข้อมูลไม่หาย |

**PO (ปั๊มผลิตเอง):** สลับเป็น PO → ช่องเป็น แผนก (408/409) *, เลข PO *, วันที่ PO (ไม่บังคับ), Vendor = โรงงาน (เลือกได้, ตั้งต้นแถว PUMA ถ้ามี) · ไม่มีกำหนด 90 วัน · ช่อง **สแกน QR** ที่ต้นฟอร์ม (K1 ทำแล้ว 28 ต.ค. 2026 — ปุ่มสแกนด้วยกล้องมือถืออย่างเดียว ไม่มีช่องเครื่องยิง ตามที่ผู้ใช้สั่ง)

## 4. ไฟล์ที่จะสร้าง/แก้
| ไฟล์ | ทำอะไร |
|---|---|
| `app/(app)/plans/new/page.tsx` | Server component: `requirePageAccess("plan-open")`, โหลด Vendor/Model ที่ใช้งาน + % QC + จำนวนวันกำหนด ส่งให้ฟอร์ม |
| `app/(app)/plans/new/OpenPlanForm.tsx` | Client: `useActionState(openPlanAction)`, คำนวณ QC/กำหนด 90 วันฝั่ง client ด้วย `rules.ts` ตัวเดียวกับ server, segmented Invoice/PO, error ใต้ช่อง |
| `app/(app)/plans/actions.ts` | เพิ่ม `lookupReceiptDocAction` (ตรวจหัวเอกสาร + แผนที่เปิดแล้ว — ข้อ 3 แถว 2/4) |
| `lib/plans/store.ts`, `lib/db/plans.ts` | เพิ่ม `listOpenOptions()` (Vendor/Model ที่ใช้งาน + Brand/ประเภทปั๊ม/ชื่อ Checklist) และรายชื่อแผนของเอกสาร |
| `components/shell/nav.ts` | `isAvailable("/plans/new")` = true |
| tests | ฟอร์ม/lookup ใน memory store + ตรวจใน Browser pane (โหมดไม่มี DB) ทั้งมือถือ 375 px และ laptop |
